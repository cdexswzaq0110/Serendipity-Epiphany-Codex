# Memory recovery

When memory may be unsafe, stop new recall and integration for the affected scope. Preserve the known revision, source information, task evidence, and an incident identifier without copying secrets into reports.

Distinguish recorded contact from proven causal use. Quarantine downstream memory and mark affected artifacts for review; unknown unrecorded activity remains unknown. Read [the recovery reference](references/recovery.md) for revocation, restoration, or external-effect cases.

Use the [runtime recovery guide](../../../docs/MEMORY_RUNBOOK.md) for actual containment and recovery operations. If it is unavailable, report that limit and preserve evidence; do not claim that isolation or recovery occurred. Operator actions need the existing user authorization and a trusted operator environment. A cleared gateway epoch does not clear an existing model context: start a fresh task with reviewed inputs.
